# CONCEPT — принципы обвязки и что из них следует

Источник: справочник «Инженерия обвязки агентов» (43 главы) — разбор в личном архиве
(`40-RESEARCH/github-harness/CONCEPT-from-pdf.md`). Здесь только то, что **меняет
решения** в этом репозитории. Принцип без следствия сюда не попал.

## Что такое обвязка

Модель даёт способности. Обвязка решает, как они подключены к работе:
что модель видит, что ей разрешено, как исполняется вызов, что возвращается,
что переживёт перезапуск и что считается доказательством готовности.

Обвязка — **управляющий контур**, а не синоним библиотеки. Поэтому её нельзя
«поставить» — её проектируют, и она состоит из решений, а не из пакетов.

## Принципы → решения в этом репозитории

| Принцип | Следствие здесь |
|---|---|
| Инструмент — часть входа модели: его имя, описание и схема видны **до** вызова | Описание скилла считается платной частью контекста; каталог не раздувается |
| Стоимость инструмента = стоимость выбора + стоимость наблюдения | Скиллы с пересекающимися описаниями не сосуществуют; результат должен быть плотным по смыслу |
| Больше инструментов — труднее выбор | Подключается только то, что доказано; лишнее удаляется, а не «пусть будет» |
| Ошибка инструмента — тоже наблюдение | Ошибки проектируются читаемыми: что случилось, можно ли повторить, какие следствия |
| Контекст конечен, и релевантность важна даже при большом окне | Короткий входной документ + глубокие слои по требованию (этот файл — пример) |
| Постепенное раскрытие вместо монолитных инструкций | `README` → `CONCEPT`/`ARCHITECTURE` → конкретный скилл; инструкции не сваливаются в один файл |
| Долговременная история и активный контекст — разные слои | Журналы и состояние не попадают в репозиторий и не смешиваются со знанием |
| Сжатие теряет информацию: `C(H) ≠ H` | Сжатие — преобразование контекста, а не удаление истории; в обвязке это учитывается |
| Скиллы надо проверять, а не считать полезными | Обязательный `EVIDENCE.md`; скилл без замера — кандидат, а не установленный |
| Механически проверяемое правило — в код, а не в текст | `harness doctor` вместо абзаца «пожалуйста, проверяйте ссылки» |
| Генератор и оценщик — разные роли | Замер делает внешний судья, не тот, кто скилл написал |
| Условия остановки и бюджеты — часть обвязки | Задача «выполнена» подтверждается наблюдаемым состоянием, а не самоотчётом |
| Идемпотентность нужна для повторов | `install` и `update` можно запускать повторно; `prune` убирает только своё |
| Параллельность создаёт проблемы согласованности | Общий каталог ссылок — одна точка правды; одновременные правки не плодят версий |
| Учётные данные — вне исполнения | Манифест хранит **имена** переменных, не значения; секреты не переносятся механизмом |
| Наблюдения имеют происхождение: содержимое, источник, доверие | Всё внешнее (веб, README, чужие репозитории) — данные, не инструкции |
| Допущения обвязки устаревают вместе с моделью и инструментом | У каждого скилла указано, на какой версии рантайма он проверен и когда перепроверять |
| Оценка показывает, помогает обвязка или просто добавляет механизмов | Раздел «чего здесь нет намеренно» и правило удалять недоказанное |

## Ментальная модель, к которой всё сводится

```
модель          даёт выученные способности
обвязка         решает, как они подключены к работе
ядро            переносит знание и процедуры между инструментами
адаптер         переводит ядро на язык конкретного инструмента
ссылки          делают так, чтобы источник правды был один
замер           отличает полезный скилл от красивого
границы         не дают сбою дотянуться до того, что дорого
```

## Антипаттерны, от которых этот репозиторий защищается

| Антипаттерн | Как защищаемся |
|---|---|
| Скилл «на всякий случай» | порог доказательности, `EVIDENCE.md` |
| Копия вместо ссылки | установка ссылками, `doctor` ловит расхождение |
| Правило, записанное текстом там, где нужен механизм | гейты в `doctor`, а не просьбы в документации |
| Монолитный файл инструкций, который не влезает в бюджет | короткий вход, глубина отдельно |
| Секреты и состояние в репозитории | `.gitignore` + `SECURITY.md` + отдельный аудит |
| «Обновим всё одной командой» | `outdated` → `update` → `prune` раздельно |
| Смешение знания об инструменте и знания о работе | ядро — про инструмент, проекты — вне репозитория |

## Чего концепция не решает

- **Не отменяет проверку результата.** Обвязка может дать внешние доказательства,
  но не заменяет суждение о том, что задача решена.
- **Не гарантирует переносимость смысла.** Скилл, доказанный на одной модели, может
  не работать на другой; поэтому замер привязан к версии рантайма.
- **Не является стандартом.** Это личная обвязка, устроенная под свои задачи;
  при переносе в другой контекст её нужно перепроверять, а не копировать.
