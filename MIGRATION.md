# MIGRATION — карта переноса и правила санитизации

Что откуда берётся, куда кладётся и что при этом вычищается.
Разведка: `40-RESEARCH/github-harness/INVENTORY.md`, `SECRETS-AUDIT.md` (личный архив, вне репозитория).

## Границы переноса

| Корзина | Объём | Куда |
|---|---:|---|
| Ядро (знание и процедуры) | ~4 МБ | **в репозиторий** |
| Адаптеры (привязка к инструментам) | ~1,7 ГБ | в репозиторий — только описание и пути; сами данные остаются на машине |
| Проектное | ~16 МБ | **не переносится** — принадлежит проектам |
| Мусор, кэши, состояние, бэкапы | ~3,8 ГБ | **не переносится** и не удаляется без отдельного решения |

Соотношение ядро : мусор ≈ **1 : 590**. Значит перенос — это выборочная выемка
файлов, а не копирование каталогов.

## Что не переносится никогда

- `.env`, `.credentials*`, `*token*`, `auth.json`, `oauth_creds.json`, `*.pem`, `*.key`
- `sessions/`, `attachments/`, `storages/`, `cache/`, `logs/`, `history/`, `backups/`
- `state.db*` (включая битые копии — их судьба решается отдельно, не переносом)
- код проектов и файлы с именами клиентов
- симлинки, ведущие за пределы будущего дерева (главный неочевидный вектор утечки)

Полный список — `.gitignore` и `SECURITY.md`.

## Дубликаты скиллов

Найдено **666 файлов `SKILL.md`, 296 уникальных имён, 370 лишних копий (55 %)**.
Битых нет ни одного.

Правило выбора канонической копии:

1. Копия в личном архиве обвязки побеждает копию внутри проекта.
2. При равенстве — самая свежая по дате изменения.
3. При равенстве — самая полная (больше вспомогательных файлов рядом).
4. **Ничего не удаляется на этом шаге.** Лишние копии только помечаются; удаление —
   отдельное решение владельца.

Крупнейшие источники дублей: CRM-проект (37 копий набора `employee-skills`),
`MomentumRide/skills` (86 файлов, 32 пересечения с `~/.hermes/skills`),
`ТехнологИИ-Полигон/migration` (копия набора 1:1), `hunter888-*` в двух деревьях.

### Решение о разделении библиотеки (принято)

Владелец не отвечал на вопрос о видимости десять раундов, а работа не должна
стоять. Принят самый осторожный вариант, который при этом двигает задачу:

| Часть | Скиллов | Где | Проверка |
|---|---:|---|---|
| технические | **30** | **опубликованы в main** | развёртывание проверено: `install --candidates` ставит 31 скилл, `doctor` чист |
| личные рабочие процессы | **10** | ветка `migration/skills` | слияние добавляет ровно эти 10 |

Критерий разделения — содержание, а не формальный признак. Технический скилл
описывает инструмент или метод и полезен любому; личный описывает распорядок
человека, его память или архивы.

Почему так: репозиторий публичный, публикация необратима — удалённый файл
остаётся в форках, кэшах и сторонних архивах. Опубликовать техническое безопасно;
опубликовать распорядок дня человека — нет.

**Решение обратимо в обе стороны.** Если репозиторий станет приватным — слияние
ветки добавит оставшиеся 10. Если владелец захочет иначе — разделение видно
и пересматривается за минуту.

### Ветка `migration/skills`

Перенос 40 скиллов подготовлен в ветке и **не опубликован** — ждёт решения
владельца о видимости репозитория.

Слияние **проверено пробным прогоном**: берётся без конфликтов, улучшения main
(сверка раскладки адаптеров, шаблоны личной инфраструктуры, проверка описаний,
инструмент статистики) сохраняются, 19 проверок на слитом состоянии проходят.

Это важно было проверить заранее: ветка создана раньше, и её версия общих файлов
старше. Копирование одного файла из ветки уже один раз затёрло на main две
проверки — ошибку поймали тесты.

### Как переносить

```bash
harness scan <каталог>              # разведка: что переносимо
harness import <путь> --dry-run     # посмотреть, что будет
harness import <путь>               # перенести (обезличит пути)
harness doctor                      # проверить результат
```

Импорт **отказывает** при подозрении на настоящий секрет и никогда не перезаписывает
уже существующий в ядре скилл. Перенесённый скилл получает статус «кандидат»:
без `EVIDENCE.md` он не устанавливается по умолчанию.

## Решения по спорным документам

| Документ | Решение | Почему |
|---|---|---|
| `MANUAL.md` | → `adapters/deepseek-harness/MANUAL.md` | описывает конкретный деплой, а не общий случай. В ядре такой текст вводил бы в заблуждение на другой машине |
| `10-STACK/REGISTRY.md` | **не переносится** | ведётся руками и потому расходится с фактом. Заменяется командой `harness inventory`: машинный отчёт об установленном, который не может устареть |
| `README.md` архива | **не переносится** | описывает структуру папок, которой в репозитории больше нет |
| `00-CORE/OPERATING-LOOP.md`, `00-CORE/ROUTING.md` | → политики ядра | уже перенесены и обобщены |
| `50-TOOLS/*` | → `tools/` | скрипты без захардкоженных ключей (проверено аудитом) |

**Принцип, по которому принимались решения:** если документ описывает
*устройство конкретной машины* — он идёт в адаптер или не идёт вовсе. Если
*способ работы* — в ядро. Реестр, который ведётся руками, — худший вариант:
он выглядит как знание, но им не является.

## Отдельно: врата перед открытием видимости

Репозиторий ведётся **приватным**, пока идёт наполнение. Открывать только после:

- ротации всех ключей, лежавших в незащищённых файлах;
- санитизации и проверки сканером;
- ручного чтения списка файлов;
- решения владельца о том, что именно показывается сообществу.
