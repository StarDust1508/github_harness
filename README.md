# github_harness — моя обвязка агентов

Один репозиторий, из которого **любой** агентский инструмент получает мои скиллы,
правила и процедуры. Ядро не привязано к инструменту; привязка живёт в адаптерах.

> Короткий вход. Глубина — по ссылкам, а не в этом файле
> (принцип постепенного раскрытия, `CONCEPT.md` §«Контекст»).

## Зачем

Сейчас мои обвязки расползлись по машине: DeepSeek Harness, Hermes, Codex, Gemini CLI,
OpenCode, папки правил. Часть скиллов дублируется, часть устарела, часть не работает.
При переезде на новую машину всё это собирается руками и теряется.

Цель: **скачал инструмент → развернул обвязку одной командой → работаешь**.

## Как это устроено

```
core/                  то, что не зависит от инструмента
  policies/            правила поведения — нужны всегда
  playbooks/           последовательности «как делать X»
  skills/<имя>/        процедура с замером: SKILL.md + EVIDENCE.md
  knowledge/           конспекты и справочники
adapters/<инструмент>/ как ядро превращается в то, что понимает конкретный инструмент
tools/harness          CLI: 12 команд, разбор — ниже
tools/bootstrap        одна команда для новой машины
tools/session-stats    что происходило в сессиях агента: вызовы, отказы, тренд
harness.yaml           единственный манифест: что есть, кому подходит, куда кладётся
```

Документы: [`CONCEPT.md`](CONCEPT.md) — принципы и решения · [`ARCHITECTURE.md`](ARCHITECTURE.md) —
слои, механизм, гейты · [`SKILLS.md`](SKILLS.md) — формат скилла и метод замера ·
[`SECURITY.md`](SECURITY.md) — что не публикуется · [`MIGRATION.md`](MIGRATION.md) —
карта переноса · [`core/README.md`](core/README.md) — навигация по ядру.

## Быстрый старт на новой машине

```bash
git clone https://github.com/StarDust1508/github_harness.git ~/harness
~/harness/tools/bootstrap        # проверит окружение, развернёт и проверит результат
```

Ничего не копируется «навсегда»: ядро подключается **ссылками**, правка в репозитории
сразу видна всем инструментам. Состояние установки — в `~/.harness/state.json`,
поэтому `prune` умеет убрать ровно то, что поставил `install`, и ничего чужого.

## Команды

| Команда | Что делает |
|---|---|
| `detect` | какие инструменты есть на машине |
| `install [инструмент]` | подключить ядро ссылками; `--candidates` включает скиллы без замера |
| `doctor` | целостность ядра: фронтматтер, дубли имён, коллизии встроенных команд, битые ссылки |
| `verify` | **самопроверка перед публикацией**: секреты, абсолютные пути, защита `.gitignore`, ссылки |
| `entrypoint [--write]` | короткий файл-указатель на ядро для файла инструкций; существующий не перезаписывает |
| `new <имя>` | заготовка скилла из шаблона |
| `scan <каталог>` | разведка: что переносимо, что требует санитизации; `--docs` — для документов |
| `import <путь>` | перенос скилла или документа с проверками и обезличиванием |
| `outdated` | что в ядре изменилось с момента установки |
| `update` | пересоздать ссылки и обновить отпечатки |
| `prune` | убрать **только свои** ссылки на исчезнувшие скиллы |
| `inventory` | машинный отчёт об установленном |

Проверки запускаются сами: локально — через `tools/hooks/pre-commit`,
в CI — на каждый push (`.github/workflows/checks.yml`). Набор проверок —
`tests/run.sh`, 19 инвариантов в подменённом домашнем каталоге.

## Диагностика поведения агента

Вопрос «почему агент плохо работает» решается по журналам, а не догадками:

```bash
./tools/session-stats --days 14     # вызовы, отказы по инструментам, тренд по неделям
./tools/session-stats --json        # машинный вывод
```

Инструмент показывает долю отказов **внутри каждого инструмента**: общая доля
обманывает, потому что редкий инструмент с частыми отказами тонет в массе вызовов
`bash` с его сотыми долями процента. Порядок разбора — скилл `agent-harness-audit`.

## Главное правило: скилл подключается по доказанной нужде

Скилл — не украшение. У каждого подключённого скилла есть `EVIDENCE.md` с замером:
задача, что было без скилла, что стало с ним, сколько это стоило токенов.
Скилл без доказательства не устанавливается по умолчанию — он остаётся кандидатом
(`status: candidate`) и включается только явным флагом.

Обоснование и метод замера — [`SKILLS.md`](SKILLS.md).
