# SKILLS — как устроен скилл и как он сюда попадает

Скилл — это **упакованная процедура**, которую модель подгружает по требованию.
Не украшение и не «полезная штука на всякий случай»: у каждого скилла есть
постоянная цена и проверяемая польза.

## Почему нужен порог доказательности

Каталог скиллов виден модели **в каждом запросе**: имя и описание каждого скилла
занимают контекст всегда, независимо от того, понадобился он или нет. Это ровно та
же цена, что у MCP-серверов и лишних инструментов.

Замер, на который мы опираемся (ProgramBench, TDD-скилл, единое отличие — наличие
скилла): автор получил **до +50 % расхода токенов при худшем результате**. Механизм
провала понятен: агент считает «тесты прошли = готово» и останавливается на неполном
решении. Независимое исследование 2026 года разбирает **307 подтверждённых сбоев**,
вызванных скиллами: 125 функциональных и 182 регрессии по эффективности.

Вывод: **скилл — это гипотеза, а не улучшение.** Гипотезу проверяют до подключения.

## Формат

```
core/skills/<имя>/
  SKILL.md       # обязателен: фронтматтер + тело
  EVIDENCE.md    # обязателен для status: proven
  ...            # ресурсы: скрипты, шаблоны, ссылки
```

Фронтматтер (ограниченный YAML, как в манифесте):

```yaml
---
name: agent-harness-audit            # kebab-case, совпадает с именем каталога
description: Что делает и КОГДА применять — это единственное, что видит модель заранее
category: diagnostics                # для инструментов, ожидающих вложенность (Hermes)
status: proven                       # proven | candidate | disabled
version: 0.1.0
---
```

**`description` — самое важное поле.** Оно решает, вызовут скилл или нет, и стоит
токенов в каждом запросе. Поэтому: сначала условие применения, потом суть.
Поля `whenToUse` в этой обвязке нет намеренно — у DeepSeek Harness оно до модели
не доходит, и полагаться на него нельзя.

## Три статуса

| Статус | Что значит | Ставится ли |
|---|---|---|
| `candidate` | есть `SKILL.md`, нет `EVIDENCE.md` | **нет** — только с флагом `--candidates` |
| `proven` | есть замер, скилл себя оправдал | да |
| `disabled` | проверен и оказался вреден или устарел | нет, и не предлагается |

Статус выводится автоматически: наличие `EVIDENCE.md` делает скилл `proven`,
если во фронтматтере не указано иное.

## Как измерять (обязательная часть `EVIDENCE.md`)

Замер должен быть таким, чтобы ему можно было поверить:

1. **Единственное различие — наличие скилла.** Всё остальное (модель, версия
   инструмента, задача, окружение) одинаково.
2. **Три метрики вместе**, а не одна:
   - качество — по **внешнему** судье, не по самоотчёту агента;
   - расход токенов на задачу;
   - число шагов или время.
3. **Не меньше трёх прогонов** на задачу, задачи стратифицированы по сложности.
   Задачи, которые решаются всегда, из замера исключаются: они не различают.
4. **Постоянная цена учитывается.** Описание скилла видно всегда — это входит в цену.
5. **Повторяемость.** В `EVIDENCE.md` указывается, на каком рантайме и версии
   замер сделан. При смене модели или рантайма замер **перепроверяется**: допущения
   обвязки устаревают.

## Что обязательно должно быть в EVIDENCE.md

- Задача, на которой мерили.
- Что было **без** скилла (и сколько это стоило).
- Что стало **со** скиллом.
- Постоянная цена (размер описания).
- Вердикт: подключён / отклонён / требует перепроверки.
- Условие перепроверки.

## Антипаттерны

| Антипаттерн | Почему плохо |
|---|---|
| Скилл «на всякий случай» | платит контекстом каждый запрос, пользы не доказал |
| Скилл-дубликат инструкции из `AGENTS.md` | две версии одного правила расходятся |
| Скилл, дублирующий встроенную возможность инструмента | модель выбирает наугад между двумя путями |
| Скилл с описанием «помогает с задачами» | модель не может решить, когда его звать |
| Скилл без проверки | неизвестно, помогает или мешает |
| Скилл, затеняющий встроенную команду | ломает ожидания пользователя (`harness doctor` это ловит) |

## Правило принятия

> Нет строки с замером — скилл не подключён.

Это не бюрократия: цена ошибки несимметрична. Неподключённый полезный скилл стоит
одного повторного решения, подключённый вредный — тихой деградации, которую трудно
заметить, потому что она выглядит как работа.
