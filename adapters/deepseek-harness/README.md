# Адаптер: DeepSeek Harness (`dsh`)

Слой перевода. **Политики здесь нет** — только то, как ядро превращается в то,
что понимает инструмент. Всё ниже проверено на установке 0.2.0-rc.2.

## Раскладка скиллов

- Формат: **плоский**. `~/.dsh/skills/<имя>/SKILL.md` — вложенность не поддерживается.
- Читаются также общие каталоги: `~/.agents/skills` (переменная `DSH_AGENTS_HOME`)
  и `<корень проекта>/.dsh/skills`, `<корень проекта>/.agents/skills`.
- Приоритет: проектные каталоги → общий пользовательский → `~/.agents/skills`.
  При совпадении имён ближайший слой побеждает безусловно.
- Форма `<имя>.md` тоже принимается — одиночный файл вместо каталога.

**Практический вывод:** ядро ставится в `~/.agents/skills` и видно инструменту
без отдельной ссылки в `~/.dsh/skills`.

## Инструкции

- Файлы: `AGENTS.md` → `CLAUDE.md` → `AGENTS.local.md` → `CLAUDE.local.md`
  в каждом каталоге от корня проекта до рабочего каталога, плюс глобальный
  `~/.dsh/AGENTS.md`.
- **Бюджет 64 КБ.** При превышении отбрасываются **широкие** файлы (ближе к корню),
  усекается бинарным поиском только самый конкретный.
  Значит: глобальный файл должен быть коротким, а глубина — в скиллах.
- Цепочка **растёт по ходу сессии**: инструкции из затронутых каталогов добавляются
  в тот же бюджет. Чем больше проектов тронуто, тем выше шанс потерять широкие правила.

## Что задаёт состав возможностей

| Что | Где | Следствие |
|---|---|---|
| Профиль | `~/.dsh/profiles/<имя>/` | набор плагинов (`dsh.profile.bundles` + патчи) |
| Пресет агента | объявляется патч-файлами в бандле | набор **инструментов** у агента |
| Домашний патч | `~/.dsh/cordis.patch.yml` | действует на все профили |

Набор инструментов задаёт **пресет**, а не профиль. Поэтому «поставить плагин» и
«дать агенту инструмент» — разные действия.

## Особенности, о которые легко споткнуться

1. **Ошибка инструмента не завершает ход.** Это наблюдение, а не сбой сессии.
2. **Параллельность по декларации.** Одновременно идут только инструменты, объявившие
   себя безопасными при параллельном вызове (чтение файлов, веб-поиск, делегирование).
   Поиск по файлам и shell — барьеры, они выполняются по одному.
3. **Правка файла требует, чтобы он был прочитан в этой же сессии.** Состояние
   держится в памяти: после возобновления сессии файл нужно перечитать,
   а у подагента своё состояние.
4. **Версия файла включает время изменения метаданных** — сторонний форматтер,
   сборка или параллельный агент ломают право на правку. Отсюда правило: не запускать
   несколько агентов на одно дерево.
5. **У веб-загрузки нет параметра таймаута** — бюджет задаётся конфигурацией.
   И она же отказывается читать PDF и переходы между доменами.
6. **Мост MCP после исчерпания попыток переподключения снимает все регистрации** —
   инструменты исчезают до перезапуска, в лог уходит одна строка. При работе с
   внешним демоном (например, движком дизайна) стоит держать большой бюджет попыток.
7. **Подагентам обычно недоступно расширение доступа** — если вложенной задаче нужен
   более широкий доступ, она возвращает это наверх.

## Проверка состояния

```bash
dsh --version                                   # версия
dsh --profile web --dump-config                 # собранное дерево плагинов
~/.dsh/sessions/<проект>/<сессия>/session.v*.jsonl.zstd   # журналы сессий
```

Журнал — **склейка независимых zstd-кадров**: распаковывать только потоково
(`zstd -d -c`). Одиночная распаковка встроенными средствами вернёт лишь первый кадр,
и статистика покажет нули.

## Что этот адаптер не делает

Не задаёт политики (они в `core/policies`), не хранит секретов, не чистит каталоги
инструмента — только ставит и снимает **свои** ссылки.
