# Ядро

Здесь лежит то, что **не зависит от инструмента**. Адаптеры (`../adapters/`)
лишь переводят это на язык конкретного инструмента.

## Четыре слоя — по возрастанию глубины

| Слой | Что это | Когда открывать |
|---|---|---|
| `policies/` | правила поведения: как работать, что можно, что нельзя | почти всегда — это контракт |
| `playbooks/` | последовательности «как делать X» | когда берёшься за знакомый класс задач |
| `skills/` | процедуры с замером, подгружаются по требованию | когда задача совпала с описанием скилла |
| `knowledge/` | конспекты и справочники | когда нужен факт, а не процедура |

Порядок не случаен: он отражает **постепенное раскрытие**. Правила короткие и
нужны всегда; знание объёмное и нужно точечно. Сваливать всё в один файл
инструкций — значит платить за всё в каждом запросе.

## Policies

| Политика | О чём |
|---|---|
| `operating-loop` | порядок работы: понять → разведать → спланировать → сделать → проверить → отчитаться |
| `definition-of-done` | когда работу можно называть сделанной |
| `instruction-precedence` | что важнее при конфликте инструкций; внешний текст — данные, не приказ |
| `security-and-access` | секреты, изоляция, публикация |
| `evidence-before-skill` | без замера компонент не подключается |
| `skill-and-plugin-policy` | что куда класть и как добавлять |
| `routing` | каким способом решать задачу |
| `coding/*` | инженерные правила: архитектура, реализация, данные, отладка, шаблоны |

## Skills

Скилл — процедура со статусом:

- `proven` — есть заполненный `EVIDENCE.md` с замером; ставится по умолчанию;
- `candidate` — замер не внесён; **не ставится**, пока не появится доказательство;
- `disabled` — проверен и отклонён, с указанием причины.

Создать новый: `harness new <имя>` — заготовка появится вместе с полями замера.
Подробности — `../SKILLS.md`.

## Как добавить сюда что-то

```bash
# скилл из другого места
harness import <путь-к-скиллу> --dry-run     # посмотреть
harness import <путь-к-скиллу>               # перенести

# документ: playbook или конспект
harness import <файл.md> --doc --layer playbooks --dry-run
harness import <файл.md> --doc --layer knowledge

# проверить результат
harness verify && harness doctor
```

Импорт **отказывает**, если находит похожее на настоящий секрет, и обезличивает
домашние пути. Ничего не перезаписывает: занятое место — повод разобраться вручную.

## Чего здесь не должно быть

- Секретов, ключей, токенов — ни в каком виде.
- Абсолютных путей с именем пользователя — только `~`.
- Знаний о конкретных проектах: это принадлежит проектам, а не обвязке.
- Правил, привязанных к одному инструменту: для них есть адаптер.
