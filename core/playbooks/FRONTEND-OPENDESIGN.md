# PLAYBOOK — фронтенд и дизайн через OpenDesign

**Область:** любой чат, любой проект. Это реализация «Правила №1» из `AGENT.md`.

## 1. Что такое OpenDesign и почему он мой первый инструмент для UI

OpenDesign (`https://open-design.ai/`, Apache-2.0, репозиторий `nexu-io/open-design`) — локальное agent-native приложение для дизайна. Отличия, которые важны мне:

- Отдаёт **реальные артефакты в коде**: HTML/CSS/компоненты, а не картинку макета. Экспорт в HTML / PDF / PPTX / MP4.
- **Дизайн-системы как файл** `DESIGN.md` — брендовый контракт, который читают и переиспользуют агенты.
- **Скиллы, шаблоны и плагины как файловая система** — их можно читать, копировать и ремиксовать из харнесса.
- **DeepSeek Harness поддерживается как нативный рантайм**: `od agent setup deepseek-harness` (структурное мышление, вызовы инструментов, обнаружение моделей, отмена, resume сессии).
- Песочница предпросмотра (sandboxed iframe), локальность данных.

## 2. Обязательный порядок работы над UI-задачей

1. **Классифицировать**: это UI/дизайн? → дальше только через этот плейбук.
2. **Определить артефакт**: прототип (web), mobile, дек, документ, дашборд, изображение, motion.
3. **Проверить доступность OpenDesign**: приложение и CLI `od` → `50-TOOLS/healthcheck.sh`.
4. **Проверить дизайн-систему проекта**: есть ли `DESIGN.md` в корне проекта.
   - Нет → создать в OpenDesign (из бренда/референсов) и положить в корень проекта.
   - Есть → работать строго в её рамках (токены, типографика, палитра).
5. **Сгенерировать/итерировать артефакт в OpenDesign** (MCP-инструменты или сам движок приложения), а не «примерно так же» вручную.
6. **Перенести в проект**: код/файлы — в структуру проекта; иконки — из Rune Icons; проверить соответствие `DESIGN.md`.
7. **Проверить качество**: контраст (WCAG 2.2 AA минимум), состояния (hover/focus/disabled/loading/error/empty), адаптивность, тёмная тема, i18n/RTL при необходимости.
8. **Зафиксировать**: если появились новые правила бренда — обновить `DESIGN.md`; если новый приём — добавить в этот плейбук.

## 3. Точки интеграции с харнессом (проверено 2026-09-19)

| Способ | Как | Когда |
|---|---|---|
| **MCP-мост** | инструменты `mcp__opendesign__*` (22 шт.) из `~/.dsh/cordis.patch.yml`, сервер `od-mcp` | Штатный путь: вызвать OpenDesign прямо из сессии |
| **CLI** | `od …` (обёртка `~/.local/bin/od` → `daemon-cli.mjs` приложения) | Экспорт, линт, направления, плагины, автоматизации — когда MCP не покрывает |
| **Рантайм** | профиль DSH `open-design` + пакет `@open-design/dsh-runtime` 0.1.0 | OpenDesign сам запускает меня как агента внутри Studio |
| Файловая система | `/Applications/Open Design.app/Contents/Resources/open-design/{skills,design-systems,design-templates,plugins}` | Чтение нужного скилла/шаблона/дизайн-системы по пути |
| Приложение | окно OpenDesign (Studio) | Живой предпросмотр и ручная правка |

### Взаимная проверка (как убедиться, что связка жива)

```sh
# OpenDesign → я: приложение видит dsh как рантайм
dsh --profile open-design --probe
# → {"v":1,"type":"probe","runtime":"open-design",...,"capabilities":{"session_resume":true,...}}

# Я → OpenDesign: MCP-сервер поднят харнессом
pgrep -fl "daemon-cli.mjs mcp"

# Список агентов, которых видит OpenDesign (в нём должен быть deepseek-harness)
# через MCP-инструмент list_agents или: node <любой MCP-клиент> …
```

Проверенный факт: OpenDesign определяет агента как **`deepseek-harness` v0.1.5-rc.2** с 8 моделями (DeepSeek V4 Flash/Pro и др.).

### Про демон (важно)

Десктопное приложение поднимает демон на **динамическом** порту, поэтому `od mcp` без параметров падает на `127.0.0.1:7456`. Обёртка `~/.local/bin/od-mcp` сама находит живой демон (перебор локальных слушающих портов + проверка `/api/health` по признаку `amrTerminalReporter`). Если приложение закрыто — MCP отвечает «cannot reach the OpenDesign daemon»; поднять: `open -a "Open Design"`.

## 4. Источник модели в OpenDesign (онбординг)

Экран «Выберите источник модели» при первом запуске OpenDesign. **Решение: «Локальный агент» → DeepSeek Harness. Логин/аккаунт OpenDesign не требуется.**

| Вариант | За | Против |
|---|---|---|
| **Локальный агент** ← выбран | Использует мои текущие креды DeepSeek (уже настроены в DSH); ноль доплат; **логин не нужен**; файлы остаются локально; `deepseek-harness` уже виден в списке агентов с 8 моделями | Нет облачных моделей OD (Claude/GPT) внутри OD; генерация изображений/видео в OD потребует BYOK или Hosted; упирается в мои лимиты |
| OpenDesign Hosted (облако OD) | Не нужны свои ключи; Claude/GPT/Gemini + картиночные модели; высокая параллельность; промо-скидка | Платная подписка + аккаунт OD; брифы и артефакты уходят в облако; двойная оплата при уже имеющемся DeepSeek |
| Собственный ключ (BYOK) | Полный контроль; можно подключить OpenAI/Gemini/OpenRouter и др. | Нужен ключ и оплата по токенам; для изображений/видео — отдельные ключи; дублирует то, что в варианте «Локальный агент» уже работает |

**Проверка, что путь «Локальный агент» жив:**

```sh
dsh --profile open-design --probe     # рантайм отвечает
dsh --profile open-design --models    # каталог моделей профиля
# список агентов глазами самого OpenDesign (MCP-инструмент list_agents) должен
# содержать запись: id=deepseek-harness, modelsCount=8
```

Модели, доступные мне внутри OpenDesign (проверено): `deepseek-official/deepseek-flash` (DeepSeek-V41-Flash, default), `deepseek-official/deepseek-v4-flash`, `deepseek-official/deepseek-v4-pro`, `deepseek-official/deepseek-v4-flash-vision-exp`, `navy/deepseek-v4-flash`, `deepseek/deepseek-chat`, `deepseek/deepseek-reasoner`.

Важно: агент `amr` в том же списке — это облачный OpenDesign (Hosted); он требует входа в аккаунт OD и подписки. Для локального пути его **не** выбираем.

**Состояние аккаунта (2026-09-19):** облачная сессия OpenDesign отключена — `od amr status` → `Status signed_out`. Для работы это не нужно: и генерация, и MCP-мост идут через локальный демон. Вернуть облако (платные модели, картинки/видео): `od amr login`.

## 5. Если OpenDesign пишет «Тест не пройден: exit 0»

Это `no_text` — OpenDesign не получил ни одного текстового кадра от рантайма. Диагностика:

```sh
# в логе демона OpenDesign:
#   [test:agent] DeepSeek Harness → no_text (exit 0)
tail -20 "$HOME/Library/Application Support/Open Design/namespaces/release-stable/logs/daemon/latest.log"

# прямая проверка связки (запускает тот же протокол, что и OpenDesign):
node ~/Desktop/DeepSeek-Harness/50-TOOLS/od-runtime-check.mjs open-design
```

Причина на 2026-09-19: адаптер OpenDesign ждал событие шины `assistant/chunk`, которое в dsh ≥ 0.1.3 заменено на `agent/assistant-stream`. Локальный патч уже установлен; при обновлении OpenDesign или dsh — перепроверить и при необходимости обновить патч по инструкции в `10-STACK/vendor/open-design-dsh-runtime-patched/PATCH-NOTES.md`.

## 6. Fallback (когда OpenDesign недоступен)

Порядок честного поведения:

1. Сообщить пользователю, что движок недоступен, и что именно не поднялось (приложение/демон/мост).
2. Предложить поднять: открыть приложение, проверить `od --version`, перезапустить демон.
3. Если работа не может ждать — делать по правилам `ux-ui-agent-skills` (DTCG-токены, WCAG-гейты) и **явно помечать** результат: «сделано без OpenDesign, дизайн-систему не прогоняли».
4. Никогда не выдавать ручную вёрстку за результат OpenDesign.

## 7. Чек-лист перед сдачей UI

- [ ] Есть/обновлён `DESIGN.md`, код ему соответствует.
- [ ] Токены (цвет/типографика/радиусы/тени) — из темы, не «магические числа».
- [ ] Контраст текста и интерактивных элементов ≥ AA.
- [ ] Все интерактивные состояния проработаны, включая focus-visible.
- [ ] Светлая и тёмная темы из одной темы (без пер-страничных палитр).
- [ ] Адаптив: узкий/средний/широкий.
- [ ] Нет хардкода цветов вне токенов; нет «AI-slop»-визуала (одинаковые карточки-тройки, случайные градиенты).
- [ ] Иконки — единый набор (Rune Icons), одинаковый стиль.
- [ ] Доступность: клавиатура, размеры целей ≥ 24px, reduced-motion.
- [ ] Прогнаны гейты:

```sh
od lint <file.html> --fail-on p1 --json            # анти-slop линтер OpenDesign
~/Desktop/DeepSeek-Harness/20-SKILLS/vendor/ux-ui/scripts/validate_contrast.py
~/Desktop/DeepSeek-Harness/20-SKILLS/vendor/ux-ui/scripts/lint_hardcodes.py <path>
```

Скиллы для этих шагов: `open-design` (движок), `ux-ui-kit` (навигация по киту), `design-tokens`, `design-component`, `design-code`, `design-review`, `a11y-audit`, `design-qa`, `apply-aesthetic`, `data-dashboard`.
