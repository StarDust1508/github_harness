# PLAYBOOK — скиллы, MCP и плагины в DSH

## 1. Где что лежит

| Слой | Путь | Ранг/порядок | Комментарий |
|---|---|---|---|
| Проектные скиллы (DSH) | `<projectRoot>/.dsh/skills` | 100 | В приоритете над пользовательскими |
| Проектные скиллы (agents) | `<projectRoot>/.agents/skills` | 200 | Совместимый корень |
| Кастомные корни | `customSkillDirs` в конфиге | 300 | Сюда можно подключить внешние каталоги скиллов |
| Пользовательские (DSH) | `~/.dsh/skills` | 400 | **Основное место глобальных скиллов** |
| Пользовательские (agents) | `~/.agents/skills` | 500 | Общий корень для агентских скиллов |
| Системные | `~/.dsh/skills/.system/` | — | Пропускается пользовательским сканом |

Проектный корень определяется ближайшим предком с `.git`; если его нет — текущей рабочей директорией.

## 2. Формат скилла

Каталог `<name>/SKILL.md` (или плоский `<name>.md`) с YAML-фронтматтером:

```yaml
---
name: my-skill
description: Что делает скилл и когда его брать (это видит модель).
whenToUse: Необязательная подсказка по триггерам.
disable-model-invocation: false   # true — скилл доступен только человеку (/команда)
user-invocable: true              # false — скрыт из человеческого меню
---
Тело: процедурное знание, шаги, шаблоны, критерии.
```

Вложенные `**/SKILL.md` **не** сканируются: только верхний уровень корня. Изменения подхватываются вотчером без перезапуска.

## 3. Как добавить скилл

1. **Поиск готового** — сначала SkillsMP (см. `40-RESEARCH/skillsmp.md`):
   `50-TOOLS/skillsmp-search.sh "<тема>"`
2. **Установка из репозитория** через экосистемный CLI (vercel-labs `skills`):
   `skills add <owner/repo> -g -a '*' -s '*' -y` — глобально и во все агентские каталоги.
3. **Локальный скилл** — авторский:
   - источник истины: `~/Desktop/DeepSeek-Harness/20-SKILLS/<name>/SKILL.md`;
   - активация: симлинк в `~/.dsh/skills` (`50-TOOLS/sync-skills.sh`).
4. **Фиксация**: строка в `10-STACK/REGISTRY.md` + запись в `00-CORE/CHANGELOG.md`.

Правило гигиены: имя скилла — kebab-case; описание — с явными триггерами («используй, когда…»), иначе модель его не выберет.

## 4. Как добавить MCP-сервер

MCP-серверы подключаются пакетом `@deepseek-ai/dsh-mcp-client`. Один сервер = одна запись в patch-слое.

Где писать:

- `~/.dsh/cordis.patch.yml` — **домашний слой, действует на все профили** (правильный выбор для глобального инструмента);
- `~/.dsh/profiles/<name>/cordis.patch.yml` — только для конкретного профиля.

Пример (stdio):

```yaml
- id: mcp-example
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: example            # [A-Za-z0-9_-]{1,32}, уникально
    transport: stdio
    command: npx
    args: ['-y', 'some-mcp-server']
    env:
      TOKEN: !!js process.env.SOME_TOKEN
    toolCallTimeoutMs: 60000
    failOnStartupError: false
    reconnect: { enabled: true, initialDelayMs: 500, maxDelayMs: 30000, maxAttempts: 10 }
```

Пример (HTTP): `transport: streamable-http`, затем `url` и `headers`.

Инструменты появляются под именами `mcp__<serverName>__<tool>` — как в Claude Code и Codex, поэтому история сессий и правила не ломаются при перезапуске.

**Цена:** описания инструментов добавляются в каждый запрос, а медленный/упавший сервер тормозит старт. Поэтому: только осознанно нужные серверы, `failOnStartupError: false` по умолчанию (чтобы сбой сервера не валил харнесс).

Проверка: `dsh --profile web --dump-config` показывает собранное дерево; далее — что инструменты `mcp__<name>__*` видны, и живой вызов.

Не поддерживается этим мостом: MCP *resources* и *prompts* — только tools.

## 5. Плагины профиля

```sh
dsh plugin --profile web add <package>      # ставит в ~/.dsh/profiles/web
dsh --profile web --dump-config             # посмотреть состав дерева
```

Порядок загрузки — массив `dsh.profile.bundles` в `~/.dsh/profiles/web/package.json`; поверх него накладываются `cordis.patch.yml` профиля, затем домашний, затем `--patch`. Режим `patchReload: live` перечитывает патчи на лету.

## 6. Критерии приёмки нового компонента

- [ ] Источник проверен: репозиторий существует, лицензия приемлема, содержимое прочитано.
- [ ] Установка воспроизводима (команда записана в реестр).
- [ ] Работает — проверено вызовом, а не фактом установки.
- [ ] Не дублирует уже установленное (иначе — замена, а не добавление).
- [ ] Стоимость оправдана (токены/вес/обслуживание).
