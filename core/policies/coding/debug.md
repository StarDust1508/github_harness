# Фаза отладки (Debug)

Главная задача — **систематическая диагностика и семантическое устранение проблем**. Сначала полная картина, потом точечный фикс.

## КОГНИТИВНОЕ ПРЕДУПРЕЖДЕНИЕ

**Ловушка "Зелёного Теста":** Успешное прохождение теста (`100% PASSED`) **НЕ ЯВЛЯЕТСЯ** доказательством корректности. Это может быть подгонка. Истинный критерий — **семантическая верификация трассы**: соответствие логов контрактам функций.

## 1. Основной сценарий (Шаги 1-4)

### Шаг 1: AGGRESSIVE_CONTEXT_GATHERING (Жадное чтение)

- Изучить traceback или описание проблемы
- **Читать ВСЕ файлы** из стека вызовов + связанные через AppGraph.xml
- Не экономить на чтении: токены чтения в 10 раз дешевле токенов генерации. Ошибочное решение из-за неполного контекста → дорогой цикл отладки
- Изучить семантическую разметку: MODULE_CONTRACT, INVARIANTS, RATIONALE, контракты функций

### Шаг 2: LOG_ANALYSIS_AND_HYPOTHESIS

- Изучить `app.log` на ошибки перед сбоем
- Найти логи `IMP:7-10` (особенно AI Belief State)
- Сопоставить фактические значения в логах с контрактами модулей
- Как правило, полноты контекста кода + логов достаточно для очевидности причины

### Шаг 3: IMPLEMENT_FIX_AND_IMMUNIZE

1. Применить точечное исправление
2. **Иммунизация:** добавить комментарий внутри исправленного блока:
   ```python
   # BUG_FIX_CONTEXT: [почему старый подход падал и почему выбран текущий]
   ```
3. Обновить CONTRACT, CHANGE_SUMMARY и логи, если логика блока изменилась

### Шаг 4: SEMANTIC_VERIFICATION

1. Запустить тесты (`pytest`)
2. **Даже при PASSED** — прочитать новые логи `IMP:7-10`
3. Убедиться: цепочка изменения состояния верна, соответствует CONTRACT, подгонки нет

## 2. Протокол эскалации (Шаг 5)

Применяется ТОЛЬКО если шаги 1-4 не помогли (баг "упорный", причина в библиотеке, фикс вызывает новые падения).

### 5.1. TDD-Изоляция
Написать падающий регрессионный тест `test_regression_[суть_бага]`, воспроизводящий проблему изолированно.

### 5.2. Динамическое зондирование
Временно внедрить сверхдетальные логи в проблемный код:
```python
logger.critical(f"[DebugProbe][IMP:10][Function] PROBE: var_X={var_X!r}")
```
Логировать: части сложных `if`-условий, дампы `__dict__`, сырые запросы к БД/API.

### 5.3. Анализ Ground Truth
Запустить регрессионный тест. `[DebugProbe]` логи дают неоспоримые факты о реальном выполнении.

### 5.4. Фикс + Очистка
Исправить баг на основе новых данных, провести семантическую верификацию, **ОБЯЗАТЕЛЬНО удалить** все `[DebugProbe]` зонды.
