# Фаза оркестрации

Главная задача — **координировать** выполнение плана через субагентов (Agent tool), управлять контекстом и отслеживать прогресс.

## 1. Когда переходить в оркестрацию

- После завершения фазы архитектуры: готов `DevelopmentPlan.md`, определены задачи
- Задача слишком большая для одного прохода — нужна декомпозиция на Feature Slices
- Несколько независимых задач, которые можно выполнить параллельно

## 2. Рабочий процесс

### Шаг 1: DECOMPOSE (Декомпозиция на задачи субагентов)

Изучить план и определить набор задач. Каждая задача = один вызов Agent tool.

**Типы задач:**
- **Code** — реализация Feature Slice (код + тесты + запуск)
- **Debug** — исправление конкретного бага с контекстом ошибки
- **Research (Ask)** — сбор информации, изучение API, поиск решений. Используется для экономии контекста основного агента: субагент исследует вопрос и возвращает сжатый ответ. В агент = Agent tool с `subagent_type="Explore"` для поиска по кодовой базе или `subagent_type="general-purpose"` для исследований

### Шаг 2: DELEGATE (Запуск субагентов)

**КРИТИЧЕСКОЕ ПРАВИЛО (Feature-Complete Subtask):**
Субагенту ставится **цельная задача на реализацию функционального среза вместе с тестами**.

- **Запрещено:** разбивать одну фичу на микрозадачи (отдельно код, отдельно тесты)
- **Правильно:** "Реализовать модуль X по DevelopmentPlan.md + написать тесты + запустить и исправить ошибки"
- Субагент завершает работу только когда код написан И успешно протестирован

**Формат промпта для субагента:**
```
Реализуй [Feature Slice] строго по DevelopmentPlan.md (путь: ./DevelopmentPlan.md).

Контекст:
- Изучи DevelopmentPlan.md и business_requirements.md
- Следуй правилам из rules/code.md (семантическая разметка, LDD, тесты)
- Используй AppGraph.xml для понимания зависимостей

Задача:
1. Реализовать [модуль/функцию] с полной семантической разметкой
2. Написать pytest-тесты с LDD-телеметрией (вывод IMP:7-10)
3. Запустить тесты, исправить ошибки
4. Обновить AppGraph.xml

Критерии завершения:
- [ ] Код соответствует DevelopmentPlan.md
- [ ] Тесты проходят
- [ ] Логи семантически верны (не подгонка)
```

**Параллелизация:**
- Независимые Feature Slices → запускать параллельно (несколько Agent tool в одном сообщении)
- Зависимые задачи → последовательно, результат предыдущей передаётся в следующую

### Шаг 3: VERIFY (Проверка результатов субагентов)

После завершения субагента:

1. **Проверить статус** — все ли критерии завершения выполнены
2. **Прочитать логи тестов** — семантическая верификация трассы (PASSED ≠ корректность)
3. **Проверить разметку** — MODULE_CONTRACT, CHANGE_SUMMARY, MODULE_MAP обновлены
4. **Проверить AppGraph.xml** — граф актуален

### Шаг 4: INTEGRATE (Интеграция и передача обратно)

1. Отметить выполненные задачи
2. Если есть проблемы — создать задачу Debug для субагента
3. Если всё ОК — вернуться в фазу архитектуры с резюме: что сделано, что осталось
4. При необходимости — запустить интеграционные тесты для проверки связей между модулями

## 3. Правила передачи контекста субагентам

- **Всегда указывать пути к документам** (DevelopmentPlan.md, requirements.txt, AppGraph.xml)
- **Всегда указывать путь к rules/** — чтобы субагент следовал тем же правилам
- **Не дублировать содержимое файлов в промпте** — указывать путь, субагент прочитает сам
- **Указывать конкретный scope** — какие файлы создавать/изменять, какие НЕ трогать

## 4. Anti-patterns

- Ставить субагенту задачу "напиши код" без указания плана и правил
- Разбивать код и тесты на разные вызовы субагентов
- Запускать зависимые задачи параллельно
- Не проверять результат субагента перед следующим шагом
- Передавать избыточный контекст в промпте вместо ссылок на файлы
