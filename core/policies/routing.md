# Маршрутизация задач

Правило верхнего уровня: **сначала классифицировать, потом действовать.**
Классификация бесплатна, неверный маршрут — дорог.

## Принцип

Инструменты в разных обвязках называются по-разному, поэтому матрица ниже
оперирует **возможностями**, а не именами. Конкретные имена — дело адаптера
(см. таблицу соответствия в конце).

## Матрица

| Ситуация | Нужная возможность | Почему так |
|---|---|---|
| Долгая задача на много раундов | цель, переживающая раунды | прогресс виден, работа не теряется |
| Веер однотипных независимых задач (аудит, миграция) | оркестрация скриптом | десятки агентов, результат собирается программно |
| 1–2 независимых куска (исследование, срез) | делегирование в фоне | не съедает контекст диалога |
| Тяжёлая команда (сборка, установка, обход) | фоновая задача | не блокирует остальную работу |
| Работа с файлами и данными | чтение, поиск, затем shell | факты из источника, а не по памяти |
| Незнакомая библиотека или API | официальная документация → минимальный пример → реализация | не изобретать API по памяти |
| Задача про интерфейс и визуал | движок дизайна, затем код | единый визуальный контракт вместо «на глазок» |
| Не хватает готового знания | поиск готового скилла → свой скилл | дешевле, чем писать с нуля |
| Изменение самой обвязки | правка ядра + журнал изменений | архитектура не должна расходиться с реальностью |
| Нужен цикл «свежих» агентов на много итераций | явная просьба пользователя | дорогой режим, не включать по своей инициативе |

## Предпочтения владельца обвязки

Это **не универсальные правила**, а мои решения: чем пользоваться, когда выбор есть.
Они переносятся вместе с обвязкой, но при переносе в другой контекст пересматриваются.

- **Интерфейс и визуал — через движок дизайна, а не «на глазок».** Любая задача про
  вёрстку, компоненты, дашборды, мобильные экраны, деки, токены, типографику,
  доступность интерфейса сначала проходит через движок дизайна и только потом
  превращается в код в проекте.
- **Иконки — из консистентного набора** с открытой лицензией, а не случайные SVG.
- **Не хватает возможности — сначала поиск готового скилла**, потом свой.
- **Режимы с высокой ценой** (циклы, веера, массовое делегирование) — только по
  явной просьбе, не по своей инициативе.

## Антипаттерны

| Антипаттерн | Почему плохо |
|---|---|
| Сразу писать код интерфейса, минуя движок дизайна | расходится визуальный контракт, дороже переделывать |
| Ставить MCP-сервер «на всякий случай» | его инструменты в каждом запросе, цена постоянная |
| Клонировать репозиторий ради одного файла | дороже и медленнее, чем забрать нужное |
| Делегировать то, что быстрее сделать самому | накладные расходы больше выигрыша |
| Включать дорогие режимы без просьбы | трата бюджета без пользы |
| Копировать вместо ссылки в обвязке | две версии одного правила расходятся |

## Эскалация

Если задача не подходит ни одному маршруту — **сформулировать маршрут явно**,
прежде чем начать, и назвать его пользователю. Молчаливое «пойду как получится» —
именно то, от чего защищает эта политика.

## Соответствие возможностей и имён инструментов

Имена зависят от обвязки; таблица показывает, как это выглядит в DeepSeek Harness.
Для другого инструмента соответствие добавляет его адаптер.

| Возможность | DeepSeek Harness |
|---|---|
| Цель на много раундов | `create_goal` / `get_goal` / `update_goal` |
| Оркестрация веером | `workflow` |
| Делегирование | `subagent` / `subagent_fork` |
| Фоновая задача | `bash run_in_background` + `job_output` |
| Список задач | `todo_write` |
| Загрузка процедуры | `skill` |
