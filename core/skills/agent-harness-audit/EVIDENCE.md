# EVIDENCE — agent-harness-audit

Замер, на котором основан скилл. Без этой страницы скилл считается кандидатом
и не подключается по умолчанию (политика `evidence-before-skill`).

## Задача

Разобраться, почему агент «не берёт инструменты» и «обещает, но не делает»
на конкретной машине, и отделить причины в обвязке от впечатления пользователя.

## Что было без скилла (метод «по интуиции»)

| Наблюдение | Итог |
|---|---|
| Гипотеза «модель стала хуже» | не подтвердилась: 0 ложных отчётов из 862 ходов |
| Гипотеза «агент не вызывает инструменты» | не подтвердилась: 41 710 вызовов, 95,7 % намерений с вызовом в том же сообщении |
| Первые попытки посчитать журналы через `zstdDecompressSync` | дали нули по всем событиям — статистика читала только заголовки |

## Что стало со скиллом (метод из процедуры)

Прогон дал конкретные, проверяемые результаты:

| Находка | Число | Как получено |
|---|---|---|
| Ошибки по инструментам | `web_fetch` 10,2 %, `present` 13 %, `edit` 6,8–9 %, `bash` 0,03 % | доля `isError` по каждому инструменту отдельно |
| Тренд | 0,53 % → 1,05 % → 1,81 % за три недели | разбивка по неделям |
| «Тихих» механизмов регресса | 15 | поиск по классам из шага 3 |
| Подтверждённых случаев «сказал и не сделал» | 0 из 862 | ручной разбор каждого попадания |
| Реальная причина впечатления | режим ленты прятал карточки вызовов; у 22 MCP-инструментов карточек нет | чтение кода клиента |
| Дрейф версии | 29 дней, 11 релизов | сверка с реестром пакетов |

## Цена

| Метрика | Без скилла | Со скиллом |
|---|---|---|
| Время до первой проверяемой гипотезы | ~2 часа блужданий | ~15 минут |
| Ложные версии (модель, провайдер, «сломался инструмент») | 3 | 0 |
| Ошибка метода (чтение только первого zstd-кадра) | допущена | поймана на шаге 1 |

## Постоянная цена

`description` скилла виден модели в каталоге при каждом запросе — примерно
90–120 токенов. Тело подгружается только по вызову.

## Вердикт

**Подключён.** Процедура превращает расплывчатый симптом в реестр проверяемых
причин и содержит ловушку, на которой легко потерять часы. Оправдывает своё
постоянное присутствие в каталоге.

## Когда перепроверить

- При смене основного рантайма (сейчас проверено на DeepSeek Harness 0.2.0-rc.2).
- При смене модели.
- Если аудит перестанет находить находки два раза подряд — вероятно, процедура
  устарела вместе с обвязкой.
