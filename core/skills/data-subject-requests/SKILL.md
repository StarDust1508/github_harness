# Запросы субъектов данных

Здесь срок **юридически значим**. Просроченный запрос — это нарушение, которое
обнаруживается по датам, и объяснение «не успели» его не отменяет.

## Когда применять

- Поступил запрос: доступ, исправление, удаление, копия, возражение, ограничение.
- Приближается срок по незакрытому запросу.
- Нужно проверить, обрабатывались ли прошлые запросы в срок.

## Когда НЕ применять

- Вопрос о рисках обработки в целом — это оценка риска, а не запрос.
- Запрос от лица, чья личность не подтверждена: сначала подтверждение,
  срок начинает течь с момента подтверждения, и это надо зафиксировать.

## Порядок

1. **Зарегистрировать в день получения.** `assurance/registers/dsr.yaml`.
   Дата получения и срок ответа — сразу, в тот же день. Запрос, лежавший
   в почте неделю, всё равно считается полученным в день поступления.
2. **Установить срок.** Отсчёт от даты получения, а не от даты, когда дошли руки.
3. **Подтвердить личность**, если есть сомнения. Фиксируется отдельно: срок
   приостанавливается на время проверки, и это нужно доказать.
4. **Собрать данные из всех систем.** Не только из той, откуда пришёл запрос.
   Перечень систем — в реестре обработки: пропущенная система означает
   неполный ответ, а неполный ответ равен отсутствию ответа.
5. **Ответить.** Способом, позволяющим подтвердить получение.
6. **Сохранить доказательство.** Отметка в реестре запросов: `evidence`.
   Запрос без доказательства недоказуем — при проверке вы не сможете показать,
   что ответили.
7. **Проверить.**
   ```bash
   tools/harness check dsr
   ```

## Когда можно отказать

Отказ возможен, но он **обосновывается**, а не формулируется. Основания
различаются по режиму (GDPR, 152-ФЗ и другие), и их применение — правовая
квалификация владельца. Общее правило одно: отказ с обоснованием лучше
молчания, а молчание — худший вариант из трёх.

## Ловушки

| Ловушка | Почему дорого |
|---|---|
| Срок считают от даты, когда занялись запросом | Нарушение по датам видно сразу; объяснение не отменяет |
| Данные собрали из одной системы | Неполный ответ неотличим от отказа, но выглядит как исполнение |
| Ответили, но не сохранили доказательство | Формально исполнили, доказать нечем |
| Запрос на удаление закрыли без удаления из резервных копий | Данные остаются; порядок ротации нужно называть честно |
| Отказ без обоснования | Худший вариант: и не исполнили, и не объяснили |
| Субъект записан по имени | Реестр сам становится источником персональных данных; нужен идентификатор |
