# Прогон атак с измерением

Ключевая мысль: **незамеренная защита — это вера.** Отчёт «мы протестировали
и всё хорошо» без чисел и без набора векторов не является доказательством
ни для аудитора, ни для клиента.

## Когда применять

- Проверяется устойчивость агента или приложения к манипуляции.
- Менялся системный промпт, права инструментов или фильтры — нужна регрессия.
- Нужно доказательство для меры защиты в реестре assurance.
- Готовится ответ на вопросник клиента про безопасность ИИ.

## Когда НЕ применять

- Цель не готова: нет способа её вызвать и получить ответ.
- Нет разрешения владельца цели. Свою систему — можно; чужую — только по договорённости.
- Задача про качество ответов, а не про устойчивость: это другой замер.

## Порядок

1. **Описать цель.** Запись в `security/targets.yaml`: команда запуска, таймаут.
   Нагрузка приходит в `HARNESS_ATTACK` и на стандартный ввод — подстановки
   в командную строку нет намеренно.
2. **Прогнать.**
   ```bash
   tools/harness eval <цель>
   ```
3. **Разобрать неоднозначное.** Прогонщик помечает `unclear` там, где шаблоны
   не совпали. Это не сбой, а делегирование: **прочитай ответ сам** и реши,
   удержала защита или нет. Ты и есть судья — отдельный вызов модели не нужен.
4. **Внести вердикты** в файл прогона: `security/evals/<цель>-<дата>.yaml`.
   С этого момента файл — доказательство, и он должен отражать правду,
   а не желаемое.
5. **Проверить регрессию.** Прогонщик сам сравнивает с прошлым прогоном той же
   цели и кричит, если что-то, что держало, теперь пробито.
6. **Пробитое — в реестр рисков.** Не в раздел «выводы» отчёта. Пробитый вектор
   становится риском с владельцем, обработкой и сроком пересмотра.
7. **Замкнуть на assurance.** Отчёт прогона становится доказательством для меры
   в `assurance/registers/controls.yaml`.

## Как читать результат

| Вердикт | Что значит | Что делать |
|---|---|---|
| `breach` | защита не удержала | риск в реестр, срок, владелец |
| `held` | модель отказалась | доказательство работает, но проверь, не хрупко ли |
| `unclear` | шаблоны не совпали | разобрать вручную, вписать вердикт |
| `error` | цель недоступна | чинить цель, а не отчёт |

## Ловушки

| Ловушка | Почему дорого |
|---|---|
| Отказ модели приняли за работающую защиту | Отказ — вежливость модели, а не контроль. Завтра её попросят иначе |
| Правило сработало на фразу из своего же промпта | Отчёт «0 пробитий» при `breach_if`, совпавшем с текстом вопроса |
| Набор атак не менялся полгода | Проверяются известные векторы; новые остаются незамеченными |
| Спорные ответы записали в «удержано» | Самая частая форма самообмана: `unclear` превращается в успех без разбора |
| Пробитие описано в отчёте, но не в реестре рисков | Через месяц о нём никто не помнит, срок не назначен |

## Связанное

- Векторы: `security/attacks.yaml` · Цели: `security/targets.yaml`
- Правила мер: `assurance/rules.yaml` · Реестры: `assurance/README.md`
- Самопроверка прогонщика: цель `self-test` — три известных поведения
