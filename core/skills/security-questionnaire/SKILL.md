# Ответы на security-вопросники

Вопросник — это проверка не знаний, а **следов**. Клиент спрашивает не «считаете
ли вы себя безопасными», а «чем подтвердите». Ответ без ссылки на документ
считается отсутствующим.

## Когда применять

- Пришёл вопросник от клиента, заказчика или при тендере.
- Клиент задаёт уточняющие вопросы по уже данному ответу.
- Нужно проверить, что ответы разным клиентам не расходятся между собой.

## Когда НЕ применять

- Вопрос про конкретную уязвимость, а не про соответствие: это работа для
  прогона атак, а не для вопросника.
- Ответа в библиотеке нет и подтвердить его нечем — сначала создаётся
  доказательство, потом ответ.

## Порядок

1. **Разобрать вопросы.** Сопоставить формулировку клиента с темой из библиотеки
   (`assurance/registers/answers.yaml`, поле `intent`). Один вопрос клиента —
   одна запись ответа.
2. **Собрать ответы.** Заполнить `assurance/registers/questionnaires/<клиент>.yaml`:
   вопрос в формулировке клиента, ссылка на ответ из библиотеки.
3. **Проверить.**
   ```bash
   tools/harness check questionnaire-<клиент>
   ```
   Проверка не даст отправить вопросник со ссылкой на несуществующий ответ
   или с ответом, у которого нет доказательства.
4. **Разобрать частичные.** Каждый ответ `partial` обязан иметь `remediation` —
   срок закрытия. Раскрывать честно: смягчённая формулировка читается
   опытным аудитором как сокрытие и стоит дороже самого пробела.
5. **Отметить адаптации.** Если ответ пришлось менять под клиента — это сигнал:
   либо ответ в библиотеке неточен, либо требование выходит за обычную практику.
   В обоих случаях правка идёт в библиотеку, а не только в этот вопросник.
6. **Отдать.** Ссылки на доказательства — рабочие, по ним клиент сможет пройти.

## Ловушки

| Ловушка | Почему дорого |
|---|---|
| Ответ по памяти, без доказательства | Один такой ответ обнуляет доверие ко всему вопроснику |
| Ответы разным клиентам расходятся | Первое, что находит внешний аудит: два документа противоречат друг другу |
| `partial` превращён в `yes` | Пробел всё равно найдут, но теперь это ещё и недостоверные сведения |
| Адаптация ответа только в вопроснике | Библиотека устаревает, следующая адаптация повторяет ту же работу |
| Доказательство устарело | Ответ формально верен, а документ, на который он ссылается, годичной давности |
| Вопросник отправлен без проверки | Разрыв ссылки или пропущенный вопрос виден клиенту, а не вам |
