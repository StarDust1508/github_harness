# Security — проверка устойчивости с измерением

Защита без замера — это вера. Здесь лежит механика, которая превращает
«мы протестировали» в набор чисел, пригодный для отчёта.

## Модель

```
attacks.yaml  →  прогонщик  →  evals/<цель>-<дата>.yaml  →  assurance
   векторы         запуск         вердикты и метрики         доказательство
```

Обвязка запускает **команду**. Как устроена команда — дело владельца цели:
`curl`, свой скрипт, локальный агент. Обвязка не знает ни про HTTP,
ни про конкретные инструменты.

## Два слоя распознавания

| Слой | Что делает | Почему так |
|---|---|---|
| машина | выполняет, сопоставляет шаблоны, считает | дёшево и воспроизводимо |
| агент-судья | разбирает `unclear` | ответы вида «здесь нет однозначного ответа» не совпадут ни с одним шаблоном, а смысл прочитать надо |

Отдельный вызов модели для судейства не нужен: агент, читающий отчёт,
и так является моделью.

## Вердикты

| Вердикт | Значение |
|---|---|
| `breach` | защита не удержала — пробитие |
| `held` | модель отказалась выполнять |
| `unclear` | шаблоны не совпали — решает агент |
| `error` | цель недоступна; чинить цель, а не отчёт |

## Правила — в данных

`attacks.yaml` содержит секцию `detection` с признаками **на уровне класса**,
чтобы не повторять одно и то же в каждой атаке. Конкретная атака может
переопределить их своим блоком `detect`.

Шаблон — подстрока без учёта регистра; с префиксом `re:` — регулярное выражение.

Порядок проверки важен: сначала признаки пробития, потом отказ модели.
Иначе отказ в ответ на успешную атаку был бы засчитан как защита.

## Регрессия

Прогонщик сам сравнивает результат с прошлым прогоном той же цели и сообщает,
что раньше держало, а теперь пробито. Это ответ на вопрос «стало ли хуже»,
который иначе задают интуицией.

## Проверка самой механики

Цель `self-test` — заглушка с тремя заранее известными поведениями.
Ожидаемый итог: **1 пробито, 14 удержано, 1 на разбор**. Если числа другие,
сломался прогонщик, а не цель. Проверка стоит в наборе тестов.

## Запуск

```bash
tools/harness eval self-test      # проверка самой механики, без сети
tools/harness eval <цель>         # прогон по своей цели
```

## Своя цель

```yaml
- id: my-app
  title: Мой сервис
  kind: chat          # chat — принимает нагрузку; static — разовая проверка файлов
  command: security/targets/http-chat.sh
  timeout: 60
  env:
    TARGET_URL: https://...
```

Нагрузка приходит двумя способами: переменная `HARNESS_ATTACK` и стандартный
ввод. Подстановки в командную строку нет намеренно — она ломается на кавычках
и открывает инъекцию в саму обвязку.

Готовые примеры обёрток — в `targets/`.
